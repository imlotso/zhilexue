## T1 手机端视频无法播放（排查 + 修复）

**客户原话**："网页手机端自适应这块视频放不了"。含义可能是：手机浏览器里点播放没反应/黑屏/转圈，也可能是弹窗布局在手机上异常。两种都要查。

### 已读到的代码事实

- 学生端播放器在 `public/js/vue-app.js` 的 `playVideo()`（约 439–475 行）。创建的标签为：`<video id="stVideo" src="…" controls autoplay playsinline preload="metadata">`。
- **没有** `error` / `stalled` 事件处理（播放失败时用户只看到转圈或黑屏，没有任何提示）；**没有** `webkit-playsinline`、`x5-playsinline`、`x5-video-player-type`（微信/QQ/UC 等内置浏览器需要）；有 `autoplay` 但没有 `muted`（移动端浏览器可能拒绝带声音的自动播放）。
- 后端 `GET /api/stu/videos/:id/play`（`app.js` 约 1655 行）返回 `v.url || store.getUrl(v.file_path)`。云存储时是 OSS 签名链接（`expires: 3600` 秒，一小时过期）或 CDN 直链（配了 `CDN_DOMAIN` 时）；本地存储时是 `/api/file?key=…&token=…`，`res.sendFile` 支持 Range。
- 视频格式：仓库里**只有** `public/admin/phonics.js` 做了 H.265/HEVC 检测（上传前拦截）。后台主视频上传（`/api/admin/videos/direct/*` 分片直传、`/videos`、`/videos/batch`）**没有**编码检测；仓库里没有 ffmpeg 转码。
- 视频弹窗 CSS 在 `public/css/app.css`（约 461–470 行及 563–564、630–632、663 行的三档响应式：`.video-box`、`.player-wrap video`）。手机最小档是 `max-height:100dvh`、`.player-wrap video{max-height:52vh}`。

### 根因：**尚未确认**。按下面顺序排查，每一步结果写进 `docs/changelog-20261107.md`

| 步骤 | 假设 | 验证方法 | 判定 |
|---|---|---|---|
| D1 | 视频编码不是 H.264+AAC（H.265、VP9、AV1，常见表现是黑屏有声音或无法播放） | 查库：`SELECT id,title,file_path,url FROM videos;`（真实库只读）看扩展名分布；取 5～10 个代表视频下载到云环境，`ffprobe -v error -show_entries stream=codec_name,codec_type,profile -of default=nw=1 文件`（没有 ffprobe 就安装 ffmpeg） | 视频流不是 `h264` 或音频不是 `aac` → 命中 |
| D2 | MP4 的 moov 在文件末尾（没做 faststart），手机在 `preload=metadata` 下长时间转圈 | `ffprobe -v trace 文件 2>&1 \| grep -m2 -E "type:'(moov\|mdat)'"`，moov 出现在 mdat 之后 → 命中 | |
| D3 | OSS/CDN 响应头不对：不支持 Range、Content-Type 不是 video/*、带了 `Content-Disposition: attachment` | 取一个学生的播放链接（`/api/stu/videos/:id/play` 返回的 `src`），`curl -sI -H "Range: bytes=0-1" "<src>"`。应为 `206`、`Accept-Ranges: bytes`、`Content-Type: video/mp4`，且没有 attachment | 任一不符 → 命中 |
| D4 | CDN 防盗链 Referer 白名单拦截了微信/QQ 内置浏览器 | 确认生产是否设了 `CDN_DOMAIN`；`curl -sI -H "Referer: " "<cdn 链接>"` 与带站点 Referer 对比状态码 | 无 Referer 返回 403 → 命中 |
| D5 | 手机内置浏览器（微信/QQ/UC/夸克）劫持 video 或拒绝 autoplay | **需要 BOBO 用真机配合**：iOS Safari、Android Chrome、微信内置浏览器各点一次播放 | 仅某个浏览器失败 → 命中 |
| D6 | 弹窗布局问题（手机底部导航遮挡控制条、`dvh` 不支持、播放区高度被压成 0） | 无头 Chrome 设备模拟 375×667、414×896，截图并读 `.video-box` / `.player-wrap` 的实际高度和 z-index | 控件被遮挡或高度异常 → 命中 |
| D7 | 一小时签名过期（暂停很久后继续） | 记录；这不是"放不了"的主因 | |

**说明**：写这份任务书时没有拿到任何实际视频文件和手机环境，不能断定是哪一条。请按 D1→D6 实际执行；D5 需要真机，请把待测清单（网址、测试账号、要点的视频）追加到 `docs/pending-human-actions.md`。若全部未命中，把 `video.error.code`、`networkState`、`readyState` 记录下来，不要硬改。

### 无论根因是什么，都要做的修复（只改 `vue-app.js` 与 `app.css`）

1. `<video>` 增加 `webkit-playsinline x5-playsinline x5-video-player-type="h5-page" x5-video-player-fullscreen="false"`，去掉 `autoplay`；用户点击"播放"后，`vid.play()` 的 Promise 如被拒绝，显示"点击视频开始播放"的提示。
2. 增加 `error` / `stalled` / `abort` 监听：失败时在播放区显示明确文案（根据 `video.error.code` 区分：不支持的格式、网络错误、解码错误），并给出"重新加载"按钮（重新请求 `/play` 取新链接，兼容签名过期）和"用浏览器打开"链接（`target="_blank"`）。
