本次基于既有安全源码增量的独立副本，集中修复后台教师扫码和手动录题。未改学生试卷库、Word、接口、权限或数据库，未推送、合并或部署。原交接目录未改动。

## 已复现并修复

### 手动录题：旧保存结果误删新草稿

1. 在 A 页面录入题目，点击“保存到待审核”，让响应延迟。
2. 离开后重新打开手动录题，继续编辑新题；或者在另一标签页编辑。
3. 原请求成功时，旧实现先无条件清除 `manual-draft`，之后才检查页面是否离开。新草稿会被清空。

同页保存中返回上一步继续修改也会丢草稿，并被旧请求带到待审核。独立复审还复现了另一条路径：B 标签页在 A 点击保存之前就写入新草稿，A 提交旧 DOM 内容，却把 B 的共享存储快照当成本次草稿并清除。

修复后按本页面初次恢复或实际写入的草稿内容记录归属，同时记录本页编辑版本。只在当前页面、当前路由、本页没有后续修改且共享草稿仍属于本次提交时清理。新修改保留，按钮恢复可用，并说明已提交的是前一版内容；写盘失败时也不因旧存储内容相同而误清当前内存草稿。仍不保证存储不可用后关闭浏览器能恢复。

### 教师扫码：旧响应串到新页面或新步骤

- 生成二维码后离开并重新进入同名页面，旧请求原先按全局 ID 写入新页面，导致出现旧二维码，而新按钮不持有对应链接。
- 重新生成期间点击“上一步”，旧响应原先会强行切回扫码步骤；旧请求的忙碌状态也阻止再次生成。
- 扫码步骤先点右侧“刷新”，再点“我已提交，查看记录”，可以同时发出两次历史请求。旧成功/失败原先会覆盖新记录，或提前解除新的加载状态。
- 复制链接后离页，剪贴板失败回调原先会改写新页面；离开教师路由时会因节点不存在抛出异常。成功回调也会在新任务上弹旧提示。

修复后 DOM 查询限定在当前页面，请求只更新仍有效的页面/步骤；历史只接受最新请求。复制结果同样检查归属，签发后链接使用提交时的学科快照。只取消旧请求对界面的影响，不声称取消服务器已执行的签发。
