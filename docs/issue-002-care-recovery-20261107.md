# ISSUE-002：班主任工作台缺失依赖与安全恢复

## 来源与故障

两个后台入口 `/admin/#/talks` 和 `/admin/#/care` 共用 `public/apps/care/index.html`。HTML 引用的 `assets/js/store.js` 不在早期安全源码快照及433/435候选内，浏览器404后 `app.js` 调用未定义的 store.load，形成白屏。

恢复来源为私有受控仓库 `imlotso/zhilexue`，提交 `0358baa7eb7cf093dd3d38f512eca44af623bc67`，路径 `public/apps/care/assets/js/store.js`，Git blob `30e70d0e92471373e01206f4c77444472b2b61bf`，原文件 SHA256 `82b104ed47d2fa462798ce8eceb80bb812b47bb3c6f1d2147b9762e9a2054374`。恢复前已核对落盘 Git blob。没有另造假数据层或假接口。

原恢复清单明确将整个模块排除，原因是内含未独立核实为合成的学生/家长示例。此次保留原集合、名单同步、设置和备份数据层实现，不分发该示例段，停用示例载入按钮；不把未核实内容放进测试或交付。

## 必要安全修正

原模块固定共享本机存储键，换账号后也能读上一账号谈话/沟通和设置。因此不能逐字节原样恢复：

- 启动先调用既有 `/api/me` 验证 admin/branch 身份，再调用权限已限制的 `/api/admin/grades-roster`。验证全部成功后才读本机记录、启用页面。
- 数据键为 `bzw.data.v2:<role>:<id>`，设置键为 `bzw.settings.v2:<role>:<id>`。身份取服务器响应，不信任本地用户资料或前端传入归属。
- 旧 `bzw.data.v1`、`bzw.settings.v1` 字节原样保留，不自动认领、导入、覆写或删除。页面只提示存在待核对旧数据；负责人确认归属并备份后再人工恢复。
- 登录变化会锁定工作台，清内存、页面、弹窗及打印内容；所有读写及设置均检查登录状态。迟到身份/名单响应不得写入新账号。
- 明确隐藏规则防止原布局 CSS 覆盖 hidden 属性。依赖失败、登录/名单失败有可见状态，不再只有空白。
- 空文件、坏JSON、无效或重复ID行、学生缺姓名、已知文本/关联字段类型错误的导入在写入前拒绝。损坏本地记录/设置不自动覆写为空数据。
- 保存前比较最后读取的原始快照，发现其他标签页更新则拒绝旧快照覆盖，要求刷新。容量不足时回滚内存至最后保存状态并保留当前输入，错误不报成功。该检查不是数据库事务，不能宣称浏览器同时写入具备完全串行化保证。

## 数据边界

这是原设计的**本机浏览器记录**，不是服务端共享数据库，不跨设备同步。分区避免正常界面串号，但同源脚本、浏览器开发者工具仍可读取 localStorage，不等于服务端访问控制。原设计保留同一操作账号此前生成的历史谈话/沟通，即使学生后来停用或转校；本次不自动删除这些历史，不把“当前花名册筛选”冒充历史记录权限重构。

旧数据恢复须先确认真实归属，不应仅凭姓名匹配认领。导入是当前账号主动选择的备份，非自动迁移。录音匿名路径是另一个安全缺陷，由独立录音修复处理；本项结果不代表音频权限通过。
