# ISSUE-004：已发布试卷再次下发入口

统一UI验收确认已发布行只显示“撤回”，而原下发弹窗绑定在草稿的“下发”按钮。先撤回会按既有后端语义清空 paper_assignments，所以无法通过正常UI直接保留名单重复下发。这与 ISSUE-001 的后端幂等缺陷分开处理。

修复：已发布行增加“追加下发 / 截止”，直接进入现有 ppAssignDialog，读取原名单和截止时间；不调用撤回、不清名单。当前可选的已有名单保持勾选并禁止误取消；停用等不可选历史收件人保留原记录但不作为新下发请求重发，新增学生可选，筛选/取消全选不改变已下发名单。原截止保留、修改、清空逻辑复用。

撤回仍保持原业务语义，但必须先确认：会清空本卷下发名单，已有作答记录保留。提示仅追加学生或修改截止应使用新入口。取消确认不发送请求。本项不改变后端、答题记录或题目内容。

新增4项真实viewPaper/弹窗函数专项红→绿，连既有截止11项共15/15。待统一真实浏览器验证按钮、保留名单、重复确认、截止保留/修改/清空、添加新学生；同时核对MySQL原 assignment/答题快照。测试员需先恢复其误点撤回清空的合成夹具，不能把此夹具变更当产品数据迁移。
