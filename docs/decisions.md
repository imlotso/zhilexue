# 决策记录

每条：日期、决定、理由。新决策追加在最后。

## D1 知识树统一（2026-11-02）

- 决定：以 `bank_trees` / `bank_tree_nodes`（`mfbank.js`）为唯一编辑源。`kind=textbook` 对应客户说的「章节树」，`kind=knowledge` 对应「知识点树」，不需要新增 kind 列。`kb_units` / `kb_points` 保留表和旧接口，只一次性复制，之后 UI 指向 `bank_trees`。
- 理由：`bank_trees` 已支持无限层级和增删改，且题目可同时挂教材节点和知识点；两套并存是客户觉得乱的原因之一。

## D2 AI 配置中心（2026-11-02）

- 决定：以 `mfcollect.js` 的 profiles 为准，`ai.js` 读取当前启用的 profile；新增 `src/ai-client.js` 适配 OpenAI 兼容、Anthropic Messages、Google Gemini 三种格式；不绑定具体厂商，密钥明文存储与现状一致。
- 理由：现有两套配置并存，profiles 已有多配置、测试连接、启用；客户只要求能配置密钥和接口。

## D3 题库与视频只做逻辑解耦（2026-11-02）

- 理由：视频本来就在对象存储；7 天内拆库会带来跨库查询、迁移和事务风险。

## D10 CI 里服务进程固定用本地存储（2026-11-02）

- 决定：`.github/workflows/ci.yml` 的 "Start server" 步骤设 `STORAGE_DRIVER=local`。
- 理由：`src/storage.js` 默认驱动是 `oss`，且 `builtin-config.js` 内置线上桶密钥，不设置的话 CI 里 smoke / word-test 的上传用例会写生产 OSS；同时 smoke 中"播放地址自带登录票据""在线预览走 inline 头"等用例本来就按本地存储的 `/api/file?token=…` 编写。
- 影响：CI 不再覆盖 OSS 驱动的真实上传；OSS / 七牛逻辑仍由 `storage-test.js`（用假密钥、不联网）覆盖。

## D11 smoke 的部署包检查在仓库缺文件时跳过（2026-11-02）

## D12 AI 演示模式用环境变量 AI_MOCK=1 开启（2026-11-02）

- 决定：`src/ai.js` 的 `getConfig().mock` 读取 `process.env.AI_MOCK === '1'`，默认 false；CI 的服务进程设 `AI_MOCK=1`。
- 理由：`ai.js` 把 mock 写死 false 后，`word-test` 的"演示模式"用例实际调真实 AI（内置 Key），CI 连不上、本地产生费用。用环境变量而不是恢复后台设置项，是为了不与"AI 配置只读 builtin-config.js"的现状冲突，T2 统一 AI 配置时可再调整。
- 影响：线上不设该变量，行为不变。

## D13 手机播放：用 videoWidth 识别"只有声音没有画面"（2026-11-02）

- 决定：`vue-app.js` 的播放弹窗除 `error` / `stalled` / `abort` 监听外，在 `loadeddata` 与 `timeupdate` 时检查 `videoWidth === 0`，命中则暂停并提示画面编码不被支持（附"重新加载""用浏览器打开"）。
- 理由：实测（Chromium + H.265 样本）浏览器解不了画面时**不触发 error 事件**：`readyState=4`、`error=null`、声音正常、画面全黑、`videoWidth=0`。只加 `error` 监听抓不到客户描述的"黑屏转圈"。
- 取舍：手机档（`max-width:640px`，沿用现有断点，任务书写的 600px 为约数）横屏视频固定 16:9，防止出错/加载前塌成 150px；竖屏视频（高>宽）加 `t1-portrait` 恢复按视频比例显示，否则会缩成 119×211。纯音频文件也会触发该提示，可接受。
- 没有做：服务器端转码；扩大前端检测到 VP9/AV1（任务书只要求把 H.265 检测抽出来复用）。

## D14 旧知识点树并入已有知识点树的"教材单元知识点"分支（2026-11-02）

- 决定：旧 `kb_units/kb_points` 复制进该 学科+学段 **已有**的知识点树（`bank_trees.kind=knowledge`），作为一级分支「教材单元知识点」→ 年级 → 单元 → 知识点；不新建第二棵树。旧 `/kbtree*` 接口保留，改为读写这个分支（`id` 变为节点 id）；复制既可用 `scripts/migrate-kb-to-trees.js`，也会在旧接口首次用到时自动做（只复制该 学科+学段）。
- 理由：题库管理页按"学段+学科 唯一一棵知识点树"取树（`trees.find`），第二棵树在那里看不到；`bank_trees` 没有年级/版本字段，年级只能靠节点层级表达。
- 取舍：① AI 拆解由"覆盖"改为"合并（只新增）"——新树上挂着 `question_nodes`，覆盖会丢关联；代价是 AI 重新生成不会清掉旧的、不再想要的节点，要到管理页手动删。② `GET /points` 取"题库文本 ∪ 树叶子"而不是只读树——旧题的 `questions.point` 是自由文本，不能让它们从下拉里消失。③ 重复执行迁移脚本会把已被手动删掉的节点按旧表补回来（脚本按旧表补齐，不记录删除）。
- 影响：学生端 `scan-tree` 会在 数学/英语 的知识点树里多出「教材单元知识点」分支（只有旧表有数据时才有）。

## D15 待审核题目 = 对现有草稿载体的统一视图，不新建表（2026-11-02）

- 决定：各入口"入库前"的题统一放进 `mf_recog_runs.drafts`（拍照识别 `image/pdf`、Word `word`、Excel `excel`、技能包 `skill`，来源标签由 `source_kind` 决定）、`mf_capture_batches.payload`（采集）；手机扫码仍是 `paper_uploads`。`/ext/pending` 把三处聚合成一个列表，逐题编辑/入库/删除。不加表、不加列。
- 理由：任务书要求不新建表；这两个载体本来就是"批次 + 题卡 JSON + 整批 commit"，只缺逐题操作。备选"给 `questions` 加 `review_status` 列"要改所有读题的查询（学生练习、组卷、题库列表…），漏一处就会把没审核的题漏给学生，风险太大。
- 逐题入库不整批结束：题卡上打 `committed`、采集项打 `_done`，批次里的题全处理完才变 `done`。老的整批 commit 端点保留（抽成 `commitRunCards` / `commitCaptureItems` 共用，行为不变，另外支持 `material` 和多个知识树节点）。
- **id 带题干指纹**：待审核项用"批次+序号"定位，序号会因删除前移；页面过期时旧 id 可能指向另一道题，点入库就入库了别的题。所以 id 末尾带题干 md5 前 8 位，操作前核对，对不上就拒绝并提示刷新。
- **手机扫码保持"先入库、后审核"**：学生上传时题目已自动入库并进了该学生的错题本（立即可用），审核 = 老师核对归类后"通过"；在待审核页点"入库"= 通过，删除 = 拒绝（连学生错题本里的这道题一起删），与原有 `uploads/:id/review` 一致。
- **技能包导入不再直接入库**（客户要求"批量录入后先进待审核"）：解析、图片上传、按 `recordKey` 去重/补图照旧，新题放进 `skill` 批次，入库时按转写包规则存（`source_type=capture`）。同一包再导入，已入库的跳过。
- 没改：题库管理页手动"新增题目"、课文习题里的 Word 批量上传（T6 范围）、老的隐藏页 `bankui.js` 的 Excel 导入仍直接入库。

## D16 Word 导入改用规则解析，不调 AI（2026-11-02）

- 决定：新增 `src/wordq.js`，按客户《word (1).docx》规则解析（题型小节标题、编号每节可重置、选项可同行、答案/解析另起一行、填空答案用「；」、`[问答题]…[问答题结束]` 多小问），不合规的题报"第几段 + 原因"，其余照常导入。录题工作台里原有的"AI 整理"Word 导入保留，也会出现在待审核（来源同为 Word导入）。
- 理由：客户规则文档给的是确定性格式，用 AI 既慢又不稳还要花钱；旧规则解析器（`docxtext.parseDocxQuestions`）要求题号在全文递增，而客户文档每个题型从 1 重新编号，规则文档里的 6 道大题只认出 1 道。
- 取舍：Word 没有行号，错误位置用"第 N 段"；多小问的问答题按小问拆成多题（共用原文放 `material`），与 Excel 阅读理解/完形的处理一致，所以"7 题"= 6 道大题 + 多出的 1 个小问；解析里的"2. xxx"列表项靠"向后看是否有选项/答案"区分于新题，认不准时并入上一题解析并给提醒，不静默吞掉。

## D17 Excel 模板兼容：忽略【例题】行；选择填空词库共用（2026-11-02）

- 决定：`parseBankWorkbook` 跳过以「【例题】」开头的整组行；`选择填空题` 小题没填干扰项时，用同一题干下所有小题的答案做共用选项。模板 `习题导入模板.xlsx` 逐字节复制到 `data/` 由接口提供，不改表头和列顺序。
- 理由：模板里的示例行此前会被当成真题导入，且 `选择填空题` 的示例（干扰项列全空）被整题拒绝——客户照示例填就会全部报错。注意客户示例自己的 5 个小题答案是 `A hospital.`、`A reporter.` ×4，去重后只有 2 个选项，导入后需要老师在待审核里补选项。

## D18 组卷：管理端和学生端共用一个抽题核心；定向下发即专属（2026-11-02）

- 决定：新增 `src/compose.js`，把"按范围抽题"收成一处：范围 = 学科/学段/年级/难度/知识点文字 + 树节点（含后代）；管理端「一键组卷」按题型数量抽（`pickByCounts`），学生端「章节组卷 / 知识点组卷」每个最小有题节点抽 1 题（`pickPerNode`）。差别只在入口：管理端有「下发」，学生自组卷不建 `papers`、只在本人名下做、交卷走 `kind=self`。
- 理由：任务书要求"管理端和学生端共用一套组卷核心，差别只在是否能下发"。此前两处各写各的 SQL，学生端按节点、管理端按文字，行为不一致。
- 范围选择：管理端组卷页新增"按章节选题 / 按知识点选题"，勾选树节点（含后代），并实时显示范围内各题型题量；仍保留"知识点文字"筛选，两者同时生效。
- **行为变更（需 BOBO 确认）**：以前一份试卷给某几个学生下发后，「我的任务」/试卷列表仍会按年级/学段/册别把它广播给其他学生（试卷没填年级时是全体学生），也能直接交卷——"广播"和"名单"是并集。现在**有名单就只对名单里的学生可见**，撤回时名单清空。这样"下发给 2 个学生"才真的只有 2 个学生能看到。
- 顺带修了一个早就存在的 bug：`GET /papers/:id` 和 `POST /submit` 查下发名单时参数顺序写反（`paper_id`/`user_id` 对调），导致被定向下发的学生（年级不匹配时）打不开自己的卷子；测试里用同年级学生没暴露它，`compose-test.js` 抓到了。
- 命名：学生端"章节测评"→"章节组卷"、"学段冲刺"→"知识点组卷"（任务书要求；仅文案，路由和接口未改）。
- 没改：学生自组卷 `kind=self` 只校验题目存在（原作者的选择：自组卷题目来自整个题库，不绑定试卷），因此学生可对任意题目 id 提交答案并写入自己的记录/错题；风险仅限本人数据，已记入待人工确认。

## D19 正确率口径与问答题处理（2026-11-02）

- 决定：习题正确率 = 该学生在某视频绑定的题里，**每题最近一次**作答答对的题数 ÷ 做过的题数；小分组 / 课程 = 合并所有视频的题再算（不是各视频百分比的平均）；一题没做过时显示"未做"而不是 0%。
- 理由：① 任务书要求"数值与手算一致"，这个口径手算最直观；② 取最近一次，学生重做答对后掌握度会上升，反复刷同一题不会把分母撑大；③ 小分组合并计算避免"一个视频 1 道题和一个视频 9 道题"被平均成一样的权重。
- 不加表：`records` 已经是每次作答的明细（user_id, question_id, is_correct），任务书说"能不加表就不加表"。
- 问答题（`type=answer`）：学生端此前没有输入框，根本答不了。现在给了固定大小的解答框，但**不自动判分**——不写 `records`、不进错题本、不计入总数和正确率，交卷后只展示参考答案让学生对照。备选"和标准答案做字符串比较"几乎必错，会把错题本灌满；"调 AI 判分"属于新能力、会产生费用，留给 BOBO 决定。
- 输入框：填空 / 问答统一用 `textarea.t6-input` 固定宽高（单空 96px、多空每空 56px、问答 176px，`resize:none`，内容多时框内滚动）；填空是单行答案，回车和粘贴的换行都转成空格。没动其它页面里的 input / textarea。
- 没做：公式输入法（T8）、听力题（T7）。

## D20 AI 配置统一：档案为准，请求只走一个客户端（2026-11-02）

- 决定：全站 AI 配置只剩「设置 → AI 配置中心」（`mf_model_profiles` 档案）一个入口；所有 AI 请求统一走 `src/ai-client.js`，按档案 `format` 选协议（OpenAI 兼容 / Anthropic / Gemini）。`ai.js` 的 `getConfig()` 改为读"当前启用的档案"，旧的顶栏「AI 配置」弹窗和 `/api/admin/ai/config`、`/report/config` 的 PUT 停用。
- 选档案的规则：该角色启用的档案 → 按 `vision→reasoning→light` 等顺序回落到别的已启用档案 → 都没有才用 `builtin-config.js`。理由：任务书验收要求"配一个接口并启用后三处都能用"，不能要求老师把五个角色都配齐；而回落内置配置保证没配置任何档案时线上行为和改版前完全一样。
- 改动面小：业务封装（`analyzePaper`、`segmentPage`、`chat` 等）的函数签名和 prompt 都没动，只换了底层请求；`mfAiInvoke` 变成 `ai.chat / visionChat` 的薄封装。
- 顺带修了 `mfAiInvoke` 回落路径的老 bug：它给 `visionChat` 传的是 `user` 和 base64 字符串，而 `visionChat` 读的是 `userText` 和 `{buf,mime}`，一旦走到回落（没配档案又带图片）就会抛错。现在 `visionChat` 同时接受两种写法。
- `AI_MOCK=1`（演示模式）仍然优先于档案——CI 靠它不调真实 AI；`visionChat` 在演示模式下直接报"演示模式下不调用视觉模型"，避免测试环境误打真实接口。
- 密钥：任务书要求保留明文存储，没动。后台界面只写不回显（`GET /profiles` 只返回 `has_key`）。
- 没做：不预置任何厂商的 Anthropic / Gemini 快捷项（任务书"不要选择或绑定具体 AI 厂商"），表单里只给各协议官方的地址写法做提示；向量角色（embedding）只支持 OpenAI 兼容格式；没有做流式输出。
- 没有真实密钥，三种格式用本机模拟服务（`aiclient-test.js`）验证请求格式；真实厂商的差异（比如个别"OpenAI 兼容"接口不支持 `response_format`，所以现有调用点都没有开 JSON 模式）需要 BOBO 拿真实密钥试一次（见 pending-human-actions）。

## D22 真题试卷：Word 上传一步生成试卷 + 入题库（2026-11-02）

- 决定：后台「试卷管理 → 上传真题试卷」选 .docx → **识别预览**（dry_run，不写库，列出题数、大题分布、不合规的题）→ 确认后**一次性**生成试卷并把题目写入题库（`source='真题试卷'`，年份 / 学科 / 年级随卷）。解析复用 T3 的 Word 规则解析（`wordq.js`），不调 AI。
- 为什么不走「待审核题目」：T3 的原则是批量导入先进待审核，但真题试卷的价值是"整张卷子"——题目要立刻按顺序挂到试卷上才能发给学生；而待审核里的题没有题库 id，无法挂卷。所以用"识别预览"这一步当审核（老师在生成前看到识别结果、不合规的题不会导入），生成后题目在题库里随时可改。如果客户要求真题也要逐题审核再入库，可以改成"先建卷，题目进待审核，入库时自动挂回这张卷"——需要给待审核项加 paper_id，改动较大，先不做（见待人工确认）。
- 大题标题：Word 里的小节标题（"单选题"…）解析后不保留位置，所以大题 = 按题型分组，先后 = 各题型第一次出现的先后；同一大题内保持文档原顺序。题型交错的文档（如洋葱样例）也能得到整齐的「一、单选题 二、填空题 三、判断题」。
- 分值：Word 里没有分值，每题默认 100 ÷ 题数（保留 1 位小数），老师可在试卷里逐题改。之前 `mfpaper` 交卷得分 = 答对题的分值之和，分值全是 0 的话永远 0 分，所以必须给默认值。交卷返回里新增 `score` / `score_total`，学生端结果页显示"得分 x / 100"。
- 年份：`mf_papers.year`（4 位数字，否则忽略）。搜索 `q` 同时匹配卷名、学科、年级和年份（搜 "2024" 能搜到年份是 2024 但名字里没写年份的卷子）。
- 学生端搜索 `mfpapers` 本来就有接口但**不支持搜索**（只有 LIMIT 200 的全量列表）——按任务书"先验证再加"，已验证没有，加了 `q / subject / grade / year`，都用参数化 SQL。试卷库排序改为年份新→旧。
- 「沿用 `papers/:id/archive`」：该接口是把试卷 HTML 归档到对象存储，和"题目入库"无关，没有改动；题目入库由 import-word 完成（任务书这句理解为"题目同时入题库"）。
- 没做：PDF / 图片版真题的一键上传（图片 / PDF 仍走「录题上传」，提交时选择"加入试卷"，该能力本来就有）。

## D23 单词页固定布局：固定高度的卡片 + 固定高度的区域 + 缩字号（2026-11-02）

- 现象（先量后改，大字号档、1280×900）：单词学习一步里，卡片高度 433 / 516 / 566 / 599 px 来回变，「写好了，下一个」按钮的位置 759 / 842 / 892 / 925 px 来回跳（最长的一个直接跑到屏幕外）；记忆学习里更夸张（卡片高度 20 种取值）。原因有三：① 单词长了会折成两行；② 释义短的 1 行、长的 3 行；③ 记忆学习里"先问认不认识"阶段释义是 `.hide`（`display:none`），之后才出现，把下面的内容顶下去。另外没有音标的词少一行。
- 做法：给全部 14 处学习卡片 `<div class="wt-card center …">` 加类名 `t13-card`（只改类名，不碰 `words.js` 逻辑），样式全部在 `app.css` 的 `.t13-*` 里：卡片固定高度（按字号档位和步骤算：单词速记①④ / 记忆学习 / 听音拼选各一个高度），卡片内「单词 / 音标 / 释义 / 提示 / 选项 / 反馈」各占固定高度的区域；没有音标 / 释义被 `.hide` 时用 `:has()` 空出同样高度；选项 2×2 固定行高。
- 放不下的文字：新增 `public/js/t13-fit.js`（约 50 行，**只改显示**，不碰 `words.js`）：对 `.t13-card` 里的 `.wq-word / .wq-mean / .wt-opt`，发现溢出就逐步缩小字号（最小 42%）。纯 CSS 做不到"按文字多少缩字号"，所以用了这个小脚本；它不读写任何业务状态，只在 DOM 变化 / 窗口变化 / 字号档位切换时量一遍。
- 字号档位（大 / 中 / 小）：卡片和各区域的高度都是 `--t13-word` / `--t13-mean`（沿用舞台已有的 `--fs-hero` / `--fs-mean`）的倍数，三档都验证过不溢出。手机竖屏新增一组更小的舞台字号变量（`@media (max-width:640px)` 里的新规则，没有改动原有选择器）。
- 代价：卡片固定高度后，短单词的卡片下方会有空白（任务书要的就是"位置不变"）；大字号档在 900px 高的屏幕上，卡片 + 按钮会超出一屏（以前遇到长单词时同样会超出），孩子可以切到「中」档。
- 没做：手机上"听音拼选"的格子 / 音节块按单词长度换行，仍有 1 行以内的高度差（已经给了最小高度，不再继续加）；短语速记、词性训练、考纲单词、连词成句等其它模式用的是同一套类名 / 区域，但这次没有各造一本书逐个量（见待人工确认）。

## D24 听力题：给现有题型附加音频，存 key 不存地址（2026-11-02）

- 决定：`questions.audio_key`（`bank/audio/…`）；题型不新增（单选 / 多选 / 判断 / 填空都可以是听力题）；学生端题目上方出现 `<audio controls playsinline preload="none">` 播放条，作答流程完全不变。

- key 白名单：只认 `bank/audio/` 目录下的 key（`audioKeyOf`）。后台接口是"传什么存什么"，不限制的话题目可以被指到 `videos/…` 的视频文件、或者带 `..` 的路径上，学生端拿到的就是能播放 / 下载任意存储对象的地址。
- 上传：没有复用 `/api/admin/upload-audio`——那个接口是给班主任录音用的，存到 `public/uploads/audio`（静态目录，不走存储，也不是 `bank/` 前缀），而任务书 T12 要求题库音频统一用 `bank/` 前缀、可迁到独立存储。所以新增 `POST /audio/upload`（同样的格式校验），走 `storage.saveFile(…, 'bank/audio')`；大小上限沿用题库上传的 25MB（比原来的 50MB 小，题库里的听力片段通常是几百 KB 到几 MB）。
- TTS：复用 `win-speak.js`（`/api/speak` 的同一个合成器）。它依赖 Windows 自带语音，Linux 上不可用，所以失败时明确提示"这台服务器没有可用的语音合成，请改用上传音频"；新增 `TTS_MOCK=1`（与 `AI_MOCK=1` 同类的演示开关）让自动化测试能走通"生成 → 存储 → 播放"。生成的音频和上传的音频是一回事（都是 `audio_key`），生成后可以先试听再保存题目。
- 播放：`<audio>` 带不了请求头，本地存储时把登录票据拼到 `/api/file?key=…&token=…` 上（和视频一样）；`preload="none"` 不提前下载；`playsinline` 防止 iOS 强制全屏。出错处理沿用 T1 的思路——给出明确的中文提示和"点这里重试"，而不是转圈。
- 没做：音频时长限制 / 转码（服务器上没有 ffmpeg 依赖）；"只能听 N 遍"之类的考试规则；一道听力材料对应多个小题（听力大题）——目前是一题一个音频，多题共用同一段音频需要各自上传 / 选同一个文件。

## D25 公式输入：本地 MathLive 懒加载；录题存 `\( … \)`，学生作答存裸 LaTeX（2026-11-02）

- 判分：任务书要求"沿用 `judge()`，不做公式等价"。唯一的改动是 `fill` 比较前先抹平**写法差异**，不是数学等价：去掉 `\( \) \[ \] $`、`\left \right \displaystyle \quad \, \; \!`、`\dfrac / \tfrac → \frac`（命令名带单词边界，`\rightarrow` 不会被误伤）。否则老师在答案框里点"插入公式"存成 `\(\sqrt{2}\)`，学生用键盘输入 `\sqrt{2}` 就会判错——两边都是"对的"，只是外壳不同。`1/2` 与 `0.5`、`\frac{2}{4}` 与 `\frac{1}{2}` 仍然互不相等，这是有意的。

- 没做：公式等价判定（按任务书）；学生端手写公式识别；题干预览（保存后在学生端看渲染，后台现有的"公式面板"和预览不动）。

- **题图 401（B9）选「按 key 签只读短票据」，没有放开匿名，也没有把登录令牌拼进图片地址**。`<img>` 带不了 Authorization 头，本地存储时题图 `/api/file?key=bank/img/…` 就 401。备选：① 让 `bank/img/` 对匿名放开——图片文件名虽是随机的，但等于把题库图片公开，不选；② 像视频那样把登录 JWT 拼进 URL（`withFileTicket`）——图片地址会出现在页面源码、Referer、日志、截图里，等于泄露整个登录态，而题图在后台列表 / 做题弹窗 / 错题本里出现得比视频多得多，不选；③ 选定：服务端在 `/api/admin`、`/api/stu` 的 JSON 响应里，给 `bank/` 目录下的图片地址补 `&ft=<过期时间>.<HMAC(key|过期时间)>`，`/api/file` 见到有效 `ft` 才放行。`ft` 只绑定这一个文件、6 小时过期、只认 `bank/` 下的 png/jpg/jpeg/gif/webp、不是 JWT（不能当登录令牌）。一处统一改在响应层，不用逐个接口改，也不用动库里存的地址（库里存的地址即使带着旧 `ft` 也会被换成新的）。代价：页面开着超过 6 小时再看图要刷新；云存储（OSS/七牛）时图片地址本来就是签名外链，不受影响。
- **代理 iframe（B5）去掉 `allow-same-origin`，不拆子域**。去掉后页面是不透明源，读不到后台的 localStorage 令牌、也碰不到 `parent.document`。付出的代价是：站点脚本自己读 `localStorage` / `document.cookie` 会抛错，所以注入脚本最先补一套内存版（cookie 仍同步进服务器的 jar）；站点发给代理的 XHR/fetch 变成跨域，所以 `/api/mfproxy`、`/api/mfcap` 放行 CORS（只放 `*`、不开 Allow-Credentials，注入脚本也把站点请求的 credentials 强制成 omit，代理本来就靠 URL 里的票据鉴权、不读 Cookie）；外层读不到 iframe 的地址，改成注入脚本 `postMessage` 告诉外层。没做独立子域：要 DNS / 证书 / 反向代理配合，放二期（遗留风险见 `pending-human-actions.md`）。
- **节点题数（B10）**：`/trees/:id/nodes` 的 `qcount` 改成「本节点及全部子孙的去重数」，另给 `qcount_own`。原来两处前端（知识树管理、智能组卷的树）自己把子节点题数加起来，换成直接用 `qcount`（否则会翻倍；顺带解决了同一道题挂在父子两处被算两次）。
- **采集知识树必须有学段 + 学科（B7）**：后端 `importTreeCore` 拒绝缺学段 / 学科的请求（前端悬浮球里加了学段、学科下拉，页面面包屑推断出的当默认值）；并入已有的同类树，同父同名节点不重复建，所以重复导入是幂等的。**以前导入产生的「学段学科为空」的孤儿树没有自动处理**（见 `pending-human-actions.md`）。
- **单题入库（B8）**：和批量入库共用同一个弹窗；学科、学段是必填，题目自己有就预选，没有就必须在弹窗里选。后端也兜底：缺学科 / 学段的题进 `failed` 并提示。手机扫码的题以前只写学科，现在入库时学段、年级也一并写进题目和上传记录。

## D31 R8 课文习题 / 课程页 / AI 浮层的几个取舍（2026-11-04）

- **小分组练习的出题口径：合并**（组内视频的题 + 小分组自己挂的题，一次做完），不是二选一。理由：学生端一个小分组就是一组视频的总和，「小分组练习」自然是把这一组都练一遍；小分组自己挂的题（比如综合题、混合运算题）放在最后，视频题按视频顺序在前。正确率也按这个合并口径算（与 T6「小分组 = 组内视频题合并计算」一致），所以小分组卡上的正确率、交卷后报告里的小分组正确率、课程页右上角的正确率三处数字始终对得上。最多 60 题。
- **一道题在课程里只挂一个位置**：`questions.section_id` 和 `video_id` 二选一（绑视频清 `section_id`，挂小分组清 `video_id`）。否则同一道题会在小分组练习里出现两次、正确率重复计数。题目本身仍只有一份，在题库管理里都查得到。
- **视频关联知识点不写 `question_nodes`，而是查询时继承**：任务书写「题目自动继承」。如果在关联时把视频的题批量写进 `question_nodes`，以后视频换了知识点、题换了视频，就要追着改，还会和老师在题库里手工挂的节点混在一起分不清。所以 `video_nodes` 只存「视频 ↔ 节点」，统计某个知识点掌握情况时用「挂在该节点（含子孙）上的题 ∪ 绑在关联了该节点的视频上的题」。另外，从课文习题弹窗打开题目编辑（复用题库的 `mfQEdit`）时，如果题目还没挂知识点，默认勾上视频关联的知识点，老师点保存才真正写入。
- **AI 浮层位置：桌面端固定在视口右下角（400×60vh），打开时做题弹窗整体向左让位**，两者完全不重叠；不选「浮在题卡上面」（会盖住选项和解析）也不选「题卡内右半屏」（爱问的做法，题卡会被挤成一半，题图 / 长题干放不下）。让位后做题弹窗宽度 = `min(1040px, 100vw − 480px)`，1440 宽屏幕上题卡还有 960px。窗口窄于 1000px（平板竖屏、手机）放不下两栏，改成底部抽屉（70vh，可最小化成右下角一个按钮）。判分前后弹窗尺寸不变的要求只针对判分本身，打开浮层时弹窗向左平移是有意为之。
- **流式实现**：后端 SSE（`text/event-stream`），前端 `fetch` + `ReadableStream` 读（`EventSource` 只能 GET、带不了 `Authorization` 头）。`ai-client.js` 加 `chatStream`：OpenAI 兼容格式（内置的阿里云百炼就是）发 `stream:true` 逐段转发；Anthropic / Gemini 先退化为一次性返回再分块推，前端体验一致，以后需要再接它们的原生流式。学生关掉面板时前端 `abort`，后端监听连接关闭并中止上游请求，不浪费调用。反向代理（nginx）需要关掉缓冲，响应头已带 `X-Accel-Buffering: no`。
- **「一步步引导」并入同一个流式接口**（`mode:'guide'`，多轮对话：AI 一次只问一个问题，学生在输入框回答），去掉原来居中遮罩的分步小窗。原 `/ai-explain`（一次性返回 JSON 步骤）接口保留不删，前端不再调用。
- **AI 老师只在判分后出现**：浮层在当前题没提交时显示「先作答并提交这道题」，避免学生先问 AI 拿答案；切题时浮层跟着当前题走，但不会自动发请求（只有点「AI 老师」或「开始讲解」才调用），控制调用量。
- **所有做题模式统一为逐题核对**：原来试卷 / 错题重做也已经是「提交本题」逐题核对（只是题号方格锁定后面的题），这次题号方格全部可以点击跳题，全部核对完才能交卷；试卷类交卷前仍有确认框。

## 2026-11-06：关闭页面后的安全重试与在途识别

上一轮“先查看批次，不能直接重发”的做法仍依赖老师人工判断。本轮新增账号/入口隔离的请求凭据，并让批次与结果原子保存；同输入同凭据可以恢复结果，响应丢失后安全重试。没有凭据的旧客户端不猜测重复内容。PDF 将来源文档和逻辑页号纳入凭据，避免重复空白页被当作同一页。

文字草稿按稳定账号保存在同一浏览器，兼容旧会话数据，不保存上传文件字节；明确提示存储失败与共享电脑清除方式。该决策取代前段“只在本标签页暂存”的范围。恢复不等于后台队列：现有单进程可以等待当前已发出的请求，关闭页面后尚未发送的后续页不会继续，进程重启后也不会假称在处理。真实识别准确性、老师内容/图文核对和 AI 建议的逐项采纳仍是独立步骤。
