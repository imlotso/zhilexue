# ISSUE-001 重复下发无损修复

## 实际缺陷与根因

433文件冻结候选在隔离测试站将同一试卷下发给两名合成学生，初次、保留截止、修改截止、清空截止四次操作产生8条下发行，后台显示「定向8人」。生产定义没有 `(paper_id,user_id)` 唯一约束，`INSERT OR IGNORE` 因而不能去重；列表 `COUNT(*)` 和名单查询又把重复行当不同学生。

此前 `astra-takeover-paper-transaction-test.js` 人为添加了生产没有的唯一索引，掩盖缺陷。该测试索引已移除；新增专项取实际 `db.js` 表定义执行。此前通过数不代表该缺陷不存在。

## 无损处理

- 下发事务的第一条表查询更新并锁定试卷行，再检查每个学生是否已有下发记录。已存在不插入，未存在才普通 INSERT。所有写入同一事务，错误全部回滚。
- 必须保持「事务首条 UPDATE 锁卷 → 查询已有名单 → 插入」顺序。MySQL 普通 START TRANSACTION 不预先建立一致性快照，因此同卷第二个写入者等前一个提交后，才建立名单快照。SQLite 同样先取写锁。
- 未传 `due_at` 时，SQL CASE 保留锁定行的最新截止；明确修改/清空才写入。不会用事务外读取的旧截止覆盖另一个已完成编辑。
- 列表改成 `COUNT(DISTINCT user_id)`，名单使用仅包含学生资料的 DISTINCT，学生端原 EXISTS 授权不变。
- 不删、不合并、不改写既有下发行的 ID、下发人或时间；不修改作答、错题、评分、主观答案或画图记录。

## 数据库增量与迁移顺序

完整 `docs/database.md` 不在安全源码副本内，此处作为增量说明，勿覆盖完整仓库原文。

启动在 `importIfEmpty` 完成后运行检查：无重复时以现有幂等DDL流程创建 `idx_passign_pair_unique` 唯一索引，列为 `(paper_id,user_id)`。空库、干净旧库均可重复启动。**不能把该唯一约束提前放进初始 CREATE TABLE**，否则含历史重复的SQLite导入会整批失败。

若存在重复，仅报告重复组数量，原行全部保留，暂不创建唯一索引。检查与建索引间若旧进程插入重复导致1062，再次统计并报告；其他DDL错误明确抛出，不伪装迁移成功。相同索引名1061由已有幂等DDL逻辑处理。

含重复旧库的应用幂等依赖所有下发写入者遵守同卷锁协议，**部署必须停旧测试应用后再单实例启动新候选，不可新旧版混跑**。这不防止旧程序或直接SQL写入重复。历史物理去重不是本补丁动作；需要完整备份、逐组核对来源及恢复验证后单独安排，不能为了建立索引先删真实行。

## 验证与交接

本机 Node24 专项17/17（新增11项加原事务6项），包含四次合法重复下发、旧重复逐行保全、截止竞争、拒绝跨分校、插入失败回滚、试卷被删后的孤儿防护、干净/重复库迁移、DDL竞争/异常与导入顺序。初次14项有7项按缺陷失败，修后通过，追加边界后17项全绿。这里只是生产处理器/SQL与内存SQLite测试，尚不能证明真实MySQL跨进程锁、完整历史导入或浏览器通过。

该专项已接入 `test:takeover`。冻结433保持不变，本修复为独立增量，无生产操作、无远端提交或部署。

## 统一环境复测清单

1. 停旧测试应用，备份当前候选、测试数据库及可恢复配置；确认只操作智乐学独立目录。不要清理现有重复，保留 ISSUE-001 原样本。
2. 应用本增量并核对清单，单实例启动。旧重复库应告警「唯一索引暂未建立」，8行历史快照不变，列表/名单为2人；再次4种截止操作新增均为0，旧8行不增长。
3. 使用新合成试卷下发同两名学生4次：物理行数2、不同学生数2、界面定向2人；`added`依次2/0/0/0。未下发学生仍无权限，旧答题历史哈希不变。
4. 在独立空库/干净库首次及重复初始化，验证pair唯一索引真实存在且约束重复INSERT。另用含重复的合成SQLite进行完整导入，验证导入成功、历史行保留、索引暂缓。
5. 真实MySQL用两个独立连接/进程并发同卷同学生下发，分别覆盖有唯一索引的干净表和保留重复无唯一索引的旧表。仅单个同步服务进程并行HTTP可能仍串行处理，不能冒充跨进程锁验证。
6. 回归截止保留/修改/清空、失败回滚、列表和学生任务、既有试卷作答与得分；之后在该修复版本跑完整聚合和浏览器验收。保存精确源码哈希与结果。

回滚代码时无需删除新增索引或数据。若在重复库回滚至旧写法，应保持测试应用停用或禁止下发，避免重新制造重复。
