## 修复后的行为

### 账号与短票据

- 普通 JWT 每次请求核对数据库当前账号。删除或角色变化使旧会话失效，停用立即拒绝；学生和分校账号按服务器本地日期检查 `expire_at`，到期当天仍可用。空到期日不限制，校长不新增到期限制。
- `/api/up` 教师扫码票据签入签发账号角色，使用时复核账号存在、角色、启用与到期状态。学生扫码票据保持原有格式兼容并复核账号。
- `/api/mfcap` 两个挂载模块及 `/api/mfproxy` 的签发/缓存票据均绑定并复核真实管理账号。代理注入的采集 token 不再是匿名管理票据。
- 旧的未绑定账号角色的采集票据和教师扫码票据需回后台重新生成；采集失效返回真正 HTTP 401，使书签工具已有的清除缓存提示能够触发。文件只读票据、`/api/report-scan`、密码重置会话策略不在本次修改范围。

### 分校学生记录

- `/api/admin/bank/uploads` 的列表/统计/逐条审核/删除/批量通过，以及 `/feedback` 的列表/统计/处理按当前学生归属分校限制；校长可管理全部记录。
- `/api/admin/bank/mf` 下统一待审核列表、角标、学生扫码编辑/AI/入库/删除及旧 `ext/review-list` 使用相同范围。普通教师录题批次仍按既有共享规则，不把全部教学资源改成私有。
- 混合批量先检查全部目标再写入，避免前半成功、后半才报越权。外部 AI 返回后再次检查关联权限。
- 历史上多个分校上传可能共用同一个 `question_id`。仅上传记录属于本校不代表可读写该关联题；存在其他分校或无有效归属学生的待审关联时拒绝分校访问，并从相关扫码、反馈与旧审核读取接口中排除。

### 待审题与学生/共享发布

`qmeta.js` 统一可见范围，以 `paper_uploads` 的 `pending` / `reviewed` 状态和有效正整数 `question_id` 为依据：

- 校长可检查和处理所有待审题。分校可检查本校独立待审题，但不能读取、编辑、删除其他分校或无有效学生归属的待审题。一个题只要存在此类关联，就拒绝分校访问。
- 学生端及公共组卷/发布/课程绑定排除全部上述待审题，包括该学生自己上传的题。正常 `approved`、共享题不受影响，测试覆盖两者仍能发布、绑定、取题和提交。
- 通用题目管理、节点/标签、分组、筛选统计、导出、AI 清洗，以及已有试卷读取/预览/导出不再成为绕过审核列表权限的入口。教师习题报告的最近作答/主观题内容、旧知识点建议同样使用题目范围；历史汇总与成绩数据保持不变，试卷记录仍由原 presentAttempt 隐藏 detail。
- 不允许把待审题加入共享试卷、课程或发布/下发；自动组卷池统一排除待审题。已有含待审题的整份学生试卷拒绝打开或交卷，避免悄悄删题改变分值。旧已发布卷仍允许撤回发布。
- 学生课程练习、核对、各提交模式、错题/复习/相似题、自组卷、主观题记录/作图读取、AI 讲解、反馈和旧题目票据在当前读取/提交时重新限制待审题。学生错题 Word 导出由服务器参数强制筛选，客户端无法关闭；教师导出使用认证路由传入的分校题目范围，校长可看全部，本校独立待审题仍可导出；客户端不能扩大范围。
- 采集/JSON 导入去重不会复用或顺带修改待审扫码题的答案、解析、标签、图片；冲突走新独立题/待审卡片路径。已审核共享题仍保留原去重补全功能。
- mf 题目/试卷 URL 的判权与实际操作使用相同 ID 解析；共用判权辅助函数不再把非法 ID 过滤成“空集合允许”。试卷无题号的合法文本行保持可用。
- 教师错题列表/Word 过滤其他分校或混合归属的待审关联，列表总数同样过滤。错题 Word 渲染结束后还复核目标学生当前归属，避免导出过程中转校后仍向旧分校发送文件。
- DOCX 渲染和试卷归档的异步步骤结束后，复核实际导出题号快照，而非可能已被修改的当前试卷题目列表。若归档存储已经完成后权限变化，不返回 key/URL；已经写入的存储对象不会自动清理。

## 兼容影响与剩余边界

- 没有删除、迁移或重写旧上传、题目、作答和成绩。遗留待审题由老师按正常审核流程处理；跨校共用题可由校长检查处置。
- 历史课程/正确率统计的题量可能仍含已隐藏待审题，因此可能出现有历史计数但可练习题为空。学生任务/试卷列表可保留元数据，打开含待审题的整卷会明确拒绝。本轮不追溯改写历史成绩，也不把显示统计当作已完成的 UI 验收。
- 本次不是所有票据、存储对象或全站所有模块的完整安全审计。真实 MySQL 查询计划/性能、事务隔离、真实 Express 中间件挂载、JWT 密码学实现、浏览器与真机、对象存储权限及并发网络行为尚未在本轮验证。
