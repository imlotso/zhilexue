# 混合媒体读取与云端只读保护验证

## 范围

基于 `76e2254642a23f2cc9b79df04d6068be581c7c74`，只修复媒体读路由和原桶保护，不改 UI、数据库初始化、schema、源媒体、配置或凭据，不全量下载 OSS。部署与真实环境验收单独进行。

- OSS 读取优先本地已有普通文件，否则保留原 key、原云端/CDN URL 及一小时 GET 签名。路由选择不是对象存在性证明；云端缺失仍由 OSS 返回真实错误，同源内联读取缺失返回 404。
- 同步/异步 URL、`readBuffer`、真实 `/api/file` 路由一致。已有本地视频通过认证的代理返回字节，不再误签云端 URL；Express `sendFile` 继续负责视频 Content-Type/Range/下载。
- 允许上传根目录本身是部署符号链接；根目录以下的符号链接、目录、路径穿越、协议/用户信息 URL 不成为本地读取目标。不修改原 key。
- `LOCAL_FOLDERS` 保留原写入/删除策略；OSS 读历史资源不再把本地缺失的该类 key 误判为必定只在本地。七牛的既有云端优先及分流规则保留。
- `STORAGE_CLOUD_READ_ONLY=1` 显式启用云端只读，默认关闭。该标记必须在启动前设置，本补丁不修改任何实际部署配置。显式只读模式下 OSS/七牛初始化失败会抛固定脱敏的 `STORAGE_CLOUD_READ_ONLY_INIT_FAILED` 并停止存储服务，不再静默回落本地，也不输出原始 SDK 错误；未启用时保留原兼容行为。它是应用保护，不替代云 IAM，也不能撤销此前已经签发的上传 URL。

## 云写入口核查

运行时代码只有 `src/storage.js` 构建 OSS/七牛 SDK。对外写入口共六个：`saveFile`、`deleteFile`、`initVideoUpload`、`signVideoPart`、`completeVideoUpload`、`abortVideoUpload`。内部的 OSS CORS 配置和七牛上传 token 也受保护。

开启只读后，在调用云 SDK 写入方法或签发上传授权之前抛出 `STORAGE_CLOUD_READ_ONLY`，中文错误明确指出云端只读；该错误不会被 storage 自身的删除/取消异常吞掉。覆盖 OSS put、multipartUpload、delete、CORS、分片初始化/完成/取消、PUT 签名，以及七牛上传策略/token/put/delete。当前 storage 没有云端 copy 入口。

调用方的批量删除先完整预检，禁止云删时不先删数据库行或保留的本地媒体；单删、清文件、视频换文件、报告删除和取消上传返回受控的只读错误，元数据编辑不受全局拦截。批量视频上传被只读拒绝时清理本请求已接收的全部临时文件，不清理原媒体。`src/report.js` 仅改删除路由，其前后的模块初始化、其他路由均保持逐字一致。

本地写入/删除仍按原策略执行；GET 签名、GET、HEAD 不受影响。没有启用或显式设为 `0` 时，写入路径与原版一致。

## 可重复的纯合成验证

在已安装项目依赖的独立工作树执行：

```sh
node --test hybrid-media-test.js
```

测试不加载真实 `db.js`、配置、凭据或应用启动，不请求 OSS。storage 在 VM 中使用真实文件系统及模拟 SDK；路由测试抽取完整生产 `/api/file` 注册块，使用真实 Express、真实 JWT/题图鉴权函数和回环 HTTP。数据仅为临时合成文件/账号。

覆盖：本地独有、云端独有、两边都有、两边都无、CDN/下载名、根目录部署链接、危险 key、符号链接逃逸、目录、权限与 I/O 异常、真实播放 URL 的登录票据、Range 206、PDF 内联、文件下载名、未登录/停用账号/失效或错误题图票据、私有录音边界、云端只读的全部入口、只读下本地写入，以及默认写入兼容，以及应用层删除/清文件/替换/取消的受控错误、批量预检和元数据编辑。

初始读取回归在原代码上 10 项中 9 项按预期失败；完成修复后通过。新增只读用例先见 OSS/七牛写入未被拒绝的失败，再加实现通过。独立 review 后补充三临时文件清理及初始化失败关闭/脱敏负测，均先见预期失败再修复；当前 23/23 通过。测试不等同于真实账号/实际原桶对象验收。

## 额外兼容验证

数据库迁移证据由部署协调者单独保管。本补丁不需要重新导入数据库；提交时比较所有原有运行时源码，除媒体相关差异外必须与基线一致，尤其保持数据库初始化输入的 SHA-256 不变。
